## At a glance

**MediGuide / PharmaCare** is a full-stack academic prototype for looking up pharmaceutical information in a Philippine context. The system combines **English/Taglish text processing, intent and prescription-status classification, BM25 retrieval over a local drug-reference corpus, a Flask NLP API, and a React-based interface**.

It was developed as an **academic NLP project**, not a certified clinical decision-support tool. Information presented by the system should be independently checked with reliable medical sources and licensed healthcare professionals.

## What the application includes

| Area | Implementation visible in this repository |
| --- | --- |
| **NLP** | Text normalization for English/Taglish queries; classification and drug-name mapping |
| **Information retrieval** | BM25 ranking of locally stored pharmaceutical records |
| **Chat responses** | Structured responses built from retrieved reference records, with warnings and educational disclaimers |
| **Web interface** | React, TypeScript, Vite, and reusable UI components |
| **Application backend** | Express APIs, SQLite persistence, account authentication, saved items and query history |
| **Pharmacy map** | Leaflet/OpenStreetMap interface and geographic pharmacy search |
| **Language-model research** | Separate TinyLlama / quantized LoRA fine-tuning and model-loading experiments |

> **Implementation distinction:** The active `model/src/inference.py` chatbot path builds structured answers deterministically from BM25-retrieved records; it does **not** call the model's text-generation method for ordinary responses. TinyLlama/LoRA work is present as a separate experimentation and model-loading component. Do not represent ordinary chatbot responses as generated by the fine-tuned LLM.

## Run locally

### Requirements

- Node.js with npm
- Python environment compatible with `model/requirements.txt` (the project's setup guide recommends Python 3.12)
- Local model/data artifacts required by the Flask service; some model configurations need substantial RAM/VRAM

### Installation

```bash
git clone https://github.com/Hermes335/PHARMACARE.git
cd PHARMACARE
npm install
python -m venv .venv
```

Activate the Python virtual environment and then install:

```bash
pip install -r model/requirements.txt
```

### Start all three development services

Run each command in a **separate terminal** at the indicated directory:

```bash
# From the repository root: frontend
npm run dev

# From the repository root: Express API
npm run server

# From model/ with the Python environment activated: Flask NLP API
cd model
python api.py
```

Defaults from the project's own setup notes: **Vite 5173 · Express 3001 · Flask 5000**. For OS-specific commands, health checks, and troubleshooting, see [`run.md`](run.md).

> The Flask service loads data from relative paths. Start it from `model/` rather than the repository root, and provide the referenced local data/model artifacts. Installation and successful operation have **not** been freshly verified by this README revision.

## Example interfaces

- `POST http://localhost:5000/chat` — NLP request with JSON `{"message": "example query"}`
- `GET http://localhost:5000/health` — health status for the NLP service
- Express routes for sign-in, saved medicine records, history, and pharmacy searching are described in [`PROGRESS.md`](PROGRESS.md).

## Model research vs. the running chatbot

The project includes **TinyLlama-1.1B fine-tuning/LoRA experiments** and code for loading model weights. Its active conversational response builder uses normalized queries, intent routing, BM25-ranked drug records, and formatted structured outputs.

Research notebooks, generated training examples, and archived implementation notes may describe other experiments. They do not demonstrate that a fine-tuned LLM generates each live response.

## Responsible use and limitations

- **Educational prototype only.** Not medical advice, diagnosis, treatment selection, or a substitute for a physician or pharmacist.
- Retrieval quality depends on the **completeness, currency, and provenance** of the local reference records.
- Warning and emergency-routing code **does not establish clinical safety or regulatory compliance**.
- Medicine prices and pharmacy information can change and should not be presented as verified real-time availability.
- User authentication/history functionality should not be used with real sensitive medical information without a privacy, security, and deployment assessment.
- Do not publish credentials, production databases, identifying health records, or logs containing sensitive information.
